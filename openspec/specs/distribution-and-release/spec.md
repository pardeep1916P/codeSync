# Multi-Browser Distribution & Release Capability Specification

## Overview
CodeSync provides an automated CI/CD deployment pipeline capable of validating, packaging, and distributing extension releases across major Chromium-based browsers (Google Chrome, Microsoft Edge, Brave, Arc, Vivaldi, Opera) and GitHub Releases.

## Requirements

### Requirement: Cross-Browser Store Deployment
- The release workflow MUST package a production Manifest V3 extension archive (`codesync-extension.zip`).
- The pipeline MUST publish updates to the **Chrome Web Store** using `chrome-webstore-upload-cli` upon version changes.
- The pipeline MUST publish updates to the **Microsoft Edge Add-ons Store** using `wdzeng/edge-addon` using API key credentials.
- The extension MUST maintain 100% native compatibility with Chromium-based browsers (**Brave**, **Arc**, **Vivaldi**, **Opera**) via standard Manifest V3 APIs.

### Requirement: Dynamic GitHub Releases
- The workflow MUST extract the extension version dynamically from `public/manifest.json`.
- The workflow MUST generate a GitHub Release tagged `v<version>` attaching production distribution archives (`codesync-extension.zip`, `dist.zip`) with autogenerated changelogs.

### Requirement: Real-Time Live Status Tracking
- The project documentation MUST display live dynamic status badges querying store APIs in real time (Chrome Web Store version, Edge store link, CI/CD build status, latest release tag).
- All browser entries in documentation tables MUST provide active direct hyperlinks to their respective installation channels.

### Requirement: Whitelisted Path Filtering
- CI/CD release workflows MUST only trigger on changes to extension source files and build configurations (`src/**`, `public/**`, `package.json`, build configs) to prevent unnecessary runner execution on non-code assets.
